# 怎样维护运营报销页面测试

[原四个页面场景](../../../tests/e2e/operator-reimbursements.spec.ts)描述新增并确认历史周期、财务访问拒绝、零影响回执和手机布局。页面只组装真实表单操作和断言；SQL准备、凭证与清理由[数据夹具核心](../../../tests/test-support/operator-reimbursement-fixture.ts)负责，[Playwright夹具](../../../tests/e2e/helpers/operator-reimbursement-fixture.ts)管理页面结束顺序和报告附件。

原账号读取与loginAs/loginWithAccount保留；受限模块没有读取或执行。原运营账号ID、2024-06-25至2024-07-24周期、88.66/66.66元、四个标题及22处页面断言/认证和账号调用保持。原两处弱SQL断言改为完整记录/版本核对，不把跳过账号或空SQL结果算通过。

## 数据从哪里来

页面写入仍从新增和确认按钮发起。新增后，独立SQL按本次UUID内容及运营ID取得真实编号、发生日、周期、金额、状态和xmin；报销后要求同一编号、88.66元、对应运营本人、真实报销时间及新版本。刷新页面后，页面和完整记录/版本仍一致。数据库角色和业务规则见[费用与报销链路](expenses-flow.md)。

HTTP 200零影响场景只在页面收到的回包上模拟失败，真实记录不得改变。用例保留弹窗/错误/无成功提示断言，再独立比较完整记录及xmin；解除路由后刷新仍显示未报销。原页面场景本轮未执行，不能用数据库测试替它标成通过。

## 准备、独占和限定清理

准备在原可选账号检查之后显式调用prepare。缺账号时原skip保持，夹具不准备数据。准备先查实际活跃运营岗位和历史周期；周期存在任何记录就拒绝，绝不按旧前缀批删。每次内容使用UUID。

该固定账号/周期要求单worker，当前项目配置workers为1；其他并行测试须使用独立实例。批量确认仍按原业务规则处理本人整个周期，用例在确认按钮之前再次核对周期只含本次记录。此检查不是跨独立测试进程共享周期的互斥锁，不能把同账号同周期分给其他并行测试。[Playwright隔离和夹具](https://playwright.dev/docs/test-fixtures)

收尾先等待本次路由结束、关闭页面停止请求，再核对先前已捕获的记录/xmin。锁后再次比较，按编号、本人、UUID内容及原xmin删除，实际影响必须为1，提交后新连接查零。无已捕获凭证时，只接纳本次UUID的未报销行；未知报销结果或同值新版本必须保留，不能把当前值写成新的期望。

不论成功还是失败，Playwright附件operator-reimbursement-fixture保存最后已核对的凭证副本、准备状态、清理确认和实际清理回执；附件不把未知状态包装为成功。附件在原套件将来获准运行时生成，本轮没有伪造页面附件。

## 验证和未完成范围

运行`node --experimental-strip-types --test scripts/learning/operator-reimbursement-fixture.test.mjs`验证12项新增风险。真实目录/行版本、实际删除及正式报销函数另外在专属无网络PG副本验证，不用SQL替身代替业务结果。

本轮实际调用正式报销函数：88.66元一行成功，重复请求0行/0元且记录不重写，财务调用被拒绝。另核对旧周期拒绝、确认前额外记录拒绝、非终态拒绝、DELETE零影响回滚、提交响应丢失的独立查零、锁前同值新xmin拒绝。各次拒绝前后168张表完整行/版本及函数权限/触发器不变；正常回收恢复本次基准，最后刻意冲突行保留到专属副本销毁。

这是实际数据库角色/RPC/触发器验证。原Auth、四个页面、390px中英文及完整回归/构建仍未执行；数据库状态标记不是真实付款。[本轮证据](../reference/verification-2026-11-11-operator-reimbursements.md)列出实际凭证与范围。

## 共享、分页和历史时间场景

[共享测试](../../../tests/e2e/operator-reimbursements-sharing.spec.ts)有六处场景声明，布局循环展开为1440、390、320px，合计八个页面场景。它保留原账号来源、登录调用和完整场景；当前受限Auth仍未执行。页面只安排搜索、筛选、确认、并发顺序及断言，[数据核心](../../../tests/test-support/reimbursement-sharing-case.ts)负责准备、凭证和回收，[Playwright夹具](../../../tests/e2e/helpers/reimbursement-sharing-fixture.ts)负责结束顺序，[页面辅助](../../../tests/e2e/helpers/reimbursement-sharing-pages.ts)负责读取/溢出断言与等待闸门。

每个场景单独生成UUID标记和209个预知主键：甲的205条历史费用、乙的99元费用、甲的其他周期7元、甲的竞态删除8元、乙的上海跨日时间样本1元。固定运营ID、原发生日期和金额不变。准备在专属SQL执行器已核验目标后，用短事务锁表，要求两名活跃运营的原费用范围完全为空；发现已有费用就停止，不能先删除旧数据。只在准备事务中用LOCAL复制模式固定跨日样本的两个时间，提交和回滚都会恢复设置。

单worker限制避免同一运行内共享固定角色；它不是跨进程的互斥锁。不同测试进程必须使用不同可重建实例。不要在现有共享实例上执行原固定账号套件，也不要绕过原登录入口声称原套件通过。

批量确认前重新核对本人整个2024-07-25周期只含本次205条记录。确认后，独立SQL要求205个原ID、金额、发生日和其他不可变字段一致，状态全部已报销、确认人是甲、时间有效、xmin更新；同事及其他周期的完整行和版本不变。删除场景只接纳指定竞态记录消失、其余208条完整不变。两个写场景都刷新并重新筛选页面，同时再次查数据库；提示和HTTP成功不作为终态凭证。

失败收尾先释放所有闸门，再排空路由、关闭页面，然后锁内比较完整图和xmin。实际删除数必须等于最后确认的208或209条，提交后独立查询为零。已知ID和本次标记同时参与查询，改名、额外插入和版本变化都会被发现。未知业务结果、清理回包丢失、零影响删除和锁内冲突均保留失败状态；关闭失败时跳过数据删除，仍尝试附件，正文、关闭、清理和附件错误不会互相覆盖。

运行`node --experimental-strip-types --test scripts/learning/reimbursement-sharing-case.test.mjs`检查11项归属/终态/未知结果及收尾风险。真实数据库另验证正式分页和报销函数、同事只读、重复提交及删除零影响；真实Chrome只核对原夹具闸门的中断收尾，数据端口明确模拟。它们都不替代原产品页面、中英文和三个视口的实际验收。[共享测试本轮证据](../reference/verification-2026-11-11-reimbursement-sharing.md)
