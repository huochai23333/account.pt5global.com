# 旅游团队与人员目录验证

本批按行为改动验证。团队切换、手动刷新与工作台同步的读回进入同一个读取 Hook。保存与成员变更留在操作 Hook，读回由视图模型按发起时的服务端快照接收。旅游客户和推广人员分别限定目录范围，再复用搜索和状态筛选。[维护指南](../explanation/tourism-collaboration-flow.md)

## 缺陷复现和验证

- 复现时，读回用新团队生成快照标识，随后被同一个页面按旧标识丢弃。两项针对性合同均失败。修复后，切换目标保存在原快照下，更换快照后晚到的旧结果被丢弃。目录合同覆盖同名团队下的推广人员、旅游客户和批发客户隔离。完整合同套件 91 项通过。
- 复用 3000 端口的 Web 服务和本地 Supabase。页面验证共 3 项通过。旅游订单、团队、任务和记录深链接覆盖中文 1440px、英文 390px，旅游订单说明页检查刷新与横向溢出，批发订单和设置入口可用。管理员与客户的通用服务说明覆盖中英文各两个宽度，检查刷新、横向溢出、按钮文字、控制台警告与 Next.js 错误层。
- 页面使用专属登录夹具。独立只读事务以该身份查询到管理员角色、旅游停用、批发启用、历史订单可见行数为 0，以及普通登录角色对 `get_visible_team_overview()` 无执行权限。3 份夹具清理记录分别确认账号、布局、资料申请记录均为 0。主库有 225 个迁移，启用计划任务和外部请求队列均为 0。
