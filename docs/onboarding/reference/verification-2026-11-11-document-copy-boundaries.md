# 多层复制与移动的失败恢复

本轮完成四类故障 × 中英文 × 1440／390px，共 16 个业务组合。使用原 URL、接口、权限、状态机和等待期限，生产源码、依赖和迁移未修改，新增待审源码为 0。整体仍为 `partial_failed`，原完整认证套件及其他未完成范围另列。

## 从哪里操作，怎样判定

按 `web-change-quality-gate` 的关键写入路径执行。实际 Chrome 从资料库页面上传来源文件、选择目录和资料、复制或剪切粘贴、继续核对。每例使用独占合成账号、客户、三层目录、三份文件及一份非空模板；移动另有一份独立顶层文件。真实 Next.js、Auth、Data API、PostgreSQL 和 Storage 均连接原本地 48021 项目。

本机 43198 代理只转发同一项目的 Auth、数据库和 Storage，故障仅匹配当前独占账号或本次路径。503 是明确的来源失败模拟；暂存实际上传／数据库响应用于在应用尚未继续时撤权；超时暂存真实来源响应 95 秒后关闭连接。没有伪造数据库终态，也没有改变原 90 秒页面期限。正常对象上传、下载及目录操作仍执行实际服务。[Storage 对象管理](https://supabase.com/docs/guides/storage/management/copy-move-objects)

预检第一次发现原 Web 已停止，旧 PID 及 3000 监听均不存在，因而在写入前退出。核对原配置摘要后恢复唯一 Web。先完成中文桌面来源失败一例并核对原表恢复，再继续其余 15 例。第一遍业务凭证均到终态，但独立控制台门禁仍失败；不能按批次状态把整轮报为通过。每次切换都先确认原进程和端口，根 `.env.local` 始终不改。

## 观测工具失败与限定重跑

第一遍的 5 个组合在续办后的目录刷新出现额外 400，服务端记录鉴权超时。观测脚本在代理所在进程连续同步执行三次 Docker SQL，阻塞事件循环；应用恢复目录读取的鉴权等待只有 8 秒。该等待由观测造成，不以最终写入成功掩盖。[Node.js 子进程文档](https://nodejs.org/download/release/v24.22.1/docs/api/child_process.html)明确同步调用阻塞事件循环。

临时探针将三类来源记录合并为单次异步数据库快照，并先等待续办触发的真实目录刷新返回 200、响应读完及网络稳定，再进行后续独立读回。生产应用没有改动。仅重跑 copy_partial-zh-1440、copy_timeout-zh-1440、copy_timeout-zh-390、copy_timeout-en-1440、copy_timeout-en-390；最终仍是 16 个唯一业务组合，重复执行不增加口径。原始完整报告及失败控制台门禁分别保存在 `browser-result-original.json`、`console-original-result.json`，新的完整控制台门禁为 `console-final-result.json`。修正前的探针与原 Web 日志也保留，失败记录没有覆盖。门禁封装首次还因 Windows 绝对路径未转换为文件 URL 而在加载阶段退出；改正后重新执行实际门禁，该启动失败日志也单独保留，不计为业务用例。

### 一份来源失败

本次随机选择的一份来源读取返回 503。实际批次响应仍为 HTTP 200，但业务状态必须是 `partial_failed`，页面显示部分完成；其他六项已有成功凭证。来源记录及真实行版本均不变。关闭故障后从页面续办同一批次，仅补办失败项，原六项凭证逐项保持。

### 复制进行中撤权

实际第一份副本上传响应尚未交付给 Web 时，目标登记仍为 `pending`；测试只把本次账号的数据库岗位改为推广员，旧登录声明仍存在。原请求与重复请求均被当前权限拒绝，访问推广员目录页显示权限提示，批次未被标为成功。来源记录和行版本仍相同。测试明确恢复该合成账号的原岗位后，从页面续办原批次，原对象与登记供同一操作继续核对。

### 页面原期限超时

真实来源响应保持 95 秒，超过页面既有的 90 秒期限。页面提示尚未确认，独立读取当时批次不得为成功。连接关闭并稳定后，再按原批次从页面继续。若后台已经保存来源失败，按部分完成办理；仍未结束则保留处理中，不能伪造失败或成功。最终仍要求同一批次全部完成、实际副本字节正确，才能判定本场景通过。

### 移动进行中撤权

选择整树和独立顶层文件。第一份文件已经由真实数据库提交移动、版本增加一次，但响应仍待交付时撤权。独立查询确认该项成功凭证保留，来源整树未改变；后续步骤与重复请求均被拒绝。恢复原岗位后只补办整树，原文件不再增加版本。最终父链、文件及目录版本、模板修订、原 Storage 路径和实际字节逐项核对。

## 最终独立核对

十二个复制组合各得到三份新文件、三层新目录和一份模板副本。新编号及路径与来源不同，副本版本、父链、大小、指纹、模板填写内容和固定版本均符合原合同。独立下载副本，与预设来源字节比较相等；来源记录及 `xmin` 仍与操作前完全相同。每例三条实际上传请求对应三个不同路径，没有重复写入。移动四例不写入新 Storage 对象，保留原路径，独立下载确认字节相同。

所有组合都刷新页面，确认同一成功批次仍可读取；额外重放原批次，结果、版本及实际上传次数保持。页面检查无框架错误层和整页横向溢出。手机工具栏沿用局部横向滚动，关键按钮均实际操作。故障产生的权限／网络错误按预期单列，原始控制台消息保留，未将它们当作正常成功通知。
