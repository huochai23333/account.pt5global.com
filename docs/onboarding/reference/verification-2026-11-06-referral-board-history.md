# 早期推荐分板与邀请码验证

2026-11-06。新增 4 份历史职责审查。最早 54 份迁移在无网络、无映射端口的专属数据库重放，45 个检查点通过。历史 SQL 保留原文及顺序。[后端阅读顺序](../../../../PT5-dropshipping-supabase/docs/onboarding/history-bootstrap.md)

| 阶段 | 独立凭证 |
| --- | --- |
| 推荐分板 | 同一合成客户有两条不同来源的旧记录。迁移后两块业务各保留一条关系及原推荐人、原时间。只有代发授权的业务员仅看见本人代发关系 |
| 移除旧表 | 旧关系表已移除，两条分板记录保留。使用原始码触发历史注册后，读回新账号角色、待启用状态、旅游推荐一行，邀请码用量增加一次 |
| 业务板及重复绑定 | 访客可区分无权和无效业务。错误跨板注册的账号、推荐和用量均为零。首次绑定返回 `linked`，重复提交返回 `already_bound`，最终关系一行、用量一。为同一推荐人开启第二块业务后，未指定板的查询要求选择，指定获授权板时有效 |
| 后缀解析的历史缺口 | 校验函数识别 `-D`，但注册前触发器仍查原字符串并拒绝插入，自助绑定也返回查无记录。账号、推荐及邀请码用量均未变化 |

第一次重放从当前结构副本带进后期的私有注册守卫，触发时调用了历史阶段尚不存在的函数。重放准备现只在副本移除这个后期触发器，原迁移安装的历史 Auth 触发器继续实际执行。本次的角色与持久记录均由数据库核对，当前注册权限整改沿用已有证据。[当前注册权限验证](verification-2026-11-06-signup-referral-write-boundary.md)
