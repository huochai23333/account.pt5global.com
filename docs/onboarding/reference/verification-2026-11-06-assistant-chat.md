## 缺陷与改动

- 取消接收流时，旧实现先释放配额，再等待失败回写。完整结果正在保存时断开也会尝试写第二次失败。修改前新增的两个回归均失败，修复后通过。共享流由同一生产者写成功或失败，再清理连接和配额。中断与超时有各自的失败原因。
- React 同一帧的两个提交可能先后读取到相同的未忙状态。当前请求引用在第一下提交时立即占用，入口离开时发出取消信号。
