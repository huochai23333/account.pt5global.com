# 订单附件丢响应与跨页恢复

本批修复原附件报告保留的上传丢响应、跨页待核对和删除丢响应缺口。采用 `web-change-quality-gate` 的关键写入路径。真实页面执行现有 Next.js、Auth、Data API、Storage 和数据库登记函数，只在浏览器传输边界制造明确故障。这是本地混合集成；没有调用外部供应商。

## 先复现，再修复

旧实现中，Storage 已写入对象但上传响应丢失后，页面结束本次操作，却没有恢复附件登记。独立查询是对象 1、附件登记 0、登记请求 0。真实故障回归退出 1，日志为 `2026-11-11T08-59-20-431Z-ae9f4b25-23da-42b7-be7b-e97f5b421b69`。本次只精确回收该订单和上传者目录，清理后为 0；原共享数据摘要恢复。

修复后同一故障执行真实上传，按原路径核对正文后登记一次，再从页面下载、比较 SHA-256 和刷新核对，通过日志为 `2026-11-11T09-10-09-476Z-92cf4aa2-7849-4f29-bd1e-7834180a955c`。初次五秒等待不足、路由次数被其他 HTTP 方法消耗和预期缺失对象的控制台断言问题分别是测试问题，保留失败日志，没有计作三个产品缺陷。

## 固定验收范围

六类故障各覆盖中文／英文、1440px／390px，共 24 个页面组合；另运行原附件学习回归 2 项，总计 26。没有把四张错误提示排版截图增加为业务场景。

| 六类故障 | 证明的结果 |
| --- | --- |
| 对象提交后上传响应丢失 | 原路径正文核实后只登记一次，没有孤立对象 |
| 登记已提交但回执及首次核对丢失 | 跨页返回后先读原记录，不重发登记 |
| 删除已提交但响应丢失 | 页面保持未确认，刷新后独立记录和对象均为 0 |
| 对象正文核对中断 | 同一标签页跨页恢复，保留对象 ID、版本和路径 |
| 下载返回不符的正文 | 阻止登记及成功提示，恢复真实正文后再确认 |
| 两文件批次第二次上传未送达却收到假成功 | 第一对象保持 ID、版本不变；逆序重选后第二文件复用原路径重试，上传共 3 次、唯一路径 2 个、登记 1 次 |

每例使用专属账号、两张专属订单，第二张为不应被修改的对照。从页面选择文件并在同一帧双击上传，经过真实存储／数据库执行，独立读取登记 ID、行版本、对象 ID／版本与正文 SHA-256，刷新后再次比对。上传不确定期间无成功提示；恢复后从页面下载的正文也必须一致。清理按实际订单／上传者前缀查找，能够回收未登记对象。

首轮 26 项得到 25 通过、1 失败，日志 `2026-11-11T09-57-40-224Z-b97a1f72-2609-4a9c-af56-fdb3eed7bbe1`。失败是原英文手机测试等待注入标记的五秒断言；现场页面已显示删除尚未确认。给原测试增加脱敏阶段记录及三十秒有界等待后，原两项定向重跑 2 通过、0 失败，日志 `2026-11-11T10-37-15-703Z-0763f7c5-6721-4ea4-b226-974e9e94005d`。这次点击至注入完成 6918ms，拦截器内两次独立 SQL 核对至中断完成 6406ms，证明默认五秒不足；原失败没有被覆盖。断言期限独立于整例期限，见[Playwright 超时说明](https://playwright.dev/docs/test-timeouts)。

当前证据覆盖固定的 26 个不同场景；执行次数是首轮 26 加定向重跑 2，没有把它写成单轮 26 项全绿。生产代码在两轮间没有修改，因此不重复已通过的 24 个故障组合。
