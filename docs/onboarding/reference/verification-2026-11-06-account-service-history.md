# 早期公告、账号与工作台服务迁移验证

2026-11-06。在无网络、无映射端口的专属数据库重放最早 42 份迁移，33 个检查点通过。新增 6 份历史职责审查，历史 SQL 保留原文和顺序。[后端阅读顺序](../../../../PT5-dropshipping-supabase/docs/onboarding/history-bootstrap.md)

| 历史检查点 | 独立凭证 |
| --- | --- |
| 公告及已读 | 三份公告中两份已发布。客户看到一份、内部账号看到两份，访客专用函数返回全员公告。重复标记已读后数据库仍只有一行 |
| 资料申请 | 重提沿用原申请编号，普通账号的自行批准被拒绝。管理员通过后，申请状态、审核人、审核时间和档案的新姓名及城市均一致 |
| 人员账号 | 业务员无法读取管理目录。管理员预检并变更合成账号后，角色、状态和日志各与同一账号匹配，操作人及说明齐全 |
| 订单锁汇率 | 只取上海当天报价，缺报价报错，人民币汇率为 1。创建时从数据库取 5.25，同一订单更新前当天报价改为 8，独立读回订单仍为 5.25，交易汇率为 5.1975 |
| 工作台反馈 | 业务员可提交，但查不到反馈表记录。管理员处理后独立读回提交人、来源、处理人和 `resolved` 状态 |
| 图片审核 | 旧待审图片和新图片各产生一行排队记录，视频为零。业务员看不到队列，管理员人工通过后独立读回 `pass`、人工来源、审核人和时间 |

首轮资料申请视图缺少底层表授权。仅重建业务 schema 的副本不会为新表复现当时的平台默认权限，单独补档案读取权后还触发了关联推荐表的权限检查。最终测试以专属副本的数据库会话取得夹具编号，由对应角色调用真实历史审核函数，并独立读回终态。采购测试同样由夹具会话读取目录编号，并补齐必填明细。当前库只读确认资料审核视图采用调用者权限，登录角色具有档案表读取权。本批未执行历史审核视图的完整角色矩阵。

当前账号变更写入允许服务角色执行，普通登录角色不可直接执行。汇率派发与图片审核派发同样拒绝普通登录角色。当前库 229 份迁移，调度关闭，启用任务和待发外部请求均为零。图片检查止于数据库登记、队列及人工终态。页面、Storage 字节和外部提供商属于各自的验收。
