# Gmail Watch 本地维护验证

后续已补齐[当前公司邮箱授权页面](verification-2026-11-11-mail-oauth-browser.md)的 8 个独立场景。下文保留本次维护函数的验证范围。

本批补齐当前候选的后台续订接线。入口为 `renewMailWatchIfNeeded`，它调用实际凭据刷新、Gmail 适配器、Supabase SDK 和 PostgREST，在专属 PostgreSQL 中保存结果。Google 令牌和 Watch 接口使用本机 HTTP 模拟。模块直接加载仓库原始文件，并对齐当前 Next 服务端的 `server-only` 标记解析。原 Web 服务由进程 31044 继续监听 3000。

## 已核对的结果

| 场景 | 业务凭证 |
| --- | --- |
| 访问凭据过期，Watch 临近到期 | 刷新 1 次、续订 1 次。独立 SQL 读取的凭据密文可解为模拟返回值，离线凭据密文保持一致，Watch 的有效期超过 5 天且失败原因清空 |
| 续订返回新游标 987654 | 待处理收件使用的原游标仍为 90，凭据和 Watch 的行版本分别为 6091、6092 |
| 续订后立即重复运行 | 返回续订 0，两个接口调用数与数据库完整行及版本均保持一致 |
| 返回已过期的期限 | 返回续订 0，保留旧期限与游标，独立查询有失败原因 |
| 返回非数字游标 | 返回续订 0，保留旧期限与游标，独立查询有失败原因 |
| 返回 503 后恢复 | 失败时保留原期限、游标与凭据版本。下一次成功后失败原因清空，游标仍为 90 |

上表对应 6 个顺序场景。合计令牌刷新 1 次、Watch 请求 5 次。每次判断均来自实际函数返回值和独立容器 SQL。专属邮箱编号为 `1b2bdab7-7511-4b08-b8b0-19024a985213`。最后按该编号逆序删除 Watch、凭据和邮箱，再独立确认三表合计为 0。

Watch 接口返回供应商当前历史位置与订阅到期时间。续订只延长订阅，收件 worker 继续从本地尚未处理的位置读取，避免跳过未归档来信。[Google Watch 接口](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users/watch) · [Gmail 推送续订说明](https://developers.google.com/workspace/gmail/api/guides/push)

## 环境与回收

专属项目 `pt5-learning-watch-2f497247` 使用真实 PostgreSQL 17.6、PostgREST 14.5、应用结构与权限，业务行从空开始。数据库只连接专属内部网络，数据位于 tmpfs，只有 PostgREST 的测试端口发布在本机回环地址。模拟来源与 API 网关均仅监听本机。

初次接线因 Docker 内部网络未发布本机端口而在准备检查处失败。补齐前端网络后保留原实例继续验证。随后两次模块加载分别遇到原 TypeScript 参数属性和 Next 服务端标记包解析问题，均在业务夹具写入前失败。独立查库三张表为零，先完成全依赖加载预检，再执行最终场景。最终原生 TypeScript 转换保留实验功能及模块类型提示。

结束后两个专属容器及两个专属网络全部回收，本机 48121／48122／48123 均已释放。临时环境文件与结构副本已删除，结构恢复日志、最终脚本、失败记录和必要凭证保留。主库邮箱、凭据、Watch 的完整行及版本摘要前后一致，任务为 269 条，计划任务关闭、活动项与外发队列均为 0。其他容器的名称与 ID 比对一致。
