# 后台任务教程最终复走

按[图片审核练习](../tutorials/backend-and-database.md#练习一追踪一次图片审核任务)使用现有 Web、Auth、Storage 与 Edge Runtime。运行时的五份媒体入口和处理文件与仓库内容一致。审核任务指向本项目本地网关，`USER_MEDIA_IMAGE_REVIEW_PROVIDER=disabled`，真实 worker 处理图片并转交人工。

| 步骤 | 中英文实际结果 |
| --- | --- |
| 页面上传 | 从「上传照片」按钮打开文件选择器。各生成 1 个媒体记录及有版本的 Storage 对象，下载 SHA-256 与输入一致 |
| 本地后台 | 审核行达到 `completed`，结果为 `disabled/manual_review`。运行终态 `succeeded`、成功 1、失败 0，图片继续等待人工 |
| 页面人工审核 | 管理员确认后资产版本改变，状态为 `pass`，审核人及审核时间有独立记录。刷新审核中心后离开待审列表 |
| 响应式读回 | 个人中心刷新后图片可解码且显示通过，中英文各检查 1440px、390px，无横向溢出 |
| 页面删除 | 每次影响 1 项，运行终态成功。独立确认媒体、审核、Storage 登记及成功目录查询为零，刷新后显示空状态 |

第一次运行把隐藏文件输入框限定在弹窗内，导致没有发出请求。核对媒体、对象、运行记录均为零后回收该账号。改用可见上传按钮和文件选择事件后重跑。产品源码、权限和任务调度保持原样。

每组关页后按本次三项精确运行编号和行版本回收测试记录。两组共回收 6 项运行、6 条尝试及对应的本地 HTTP 响应。账号、会话、档案和岗位关联均独立查零。主项目历史运行总数仍为 269，原运行、尝试和告警的摘要一致，调度 off，启用任务和请求队列均为 0。

证据、截图和独立读回位于 Web `output/learning-media-tutorial-20261111/`，原始日志位于 `output/test-runs/`。这是本地混合集成，真实供应商、原受限浏览器套件及上传部署继续保留各自状态。
