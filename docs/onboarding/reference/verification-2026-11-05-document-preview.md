## 缺陷与修复

真实页面已能看到文件登记，但 Storage 对象缺失。旧预览窗把错误正文交给 iframe，页面没有给出可重试提示。原中文桌面红例日志 `2026-11-05T15-02-37-372Z-4c139359-583d-4ee5-9449-80fb728157c5`。

预览窗在确认原生内容后才显示 iframe。失败显示中英文提示，点击重试后按原文件编号重新授权和读回。预览错误响应可由同站预览窗识别，继续禁止跨站嵌入及外部资源。PDF 加载期间预留最终大小，避免 Chrome 查看器初始化时拿到零高度。

批量确认窗重新读取清单时清除旧清单，加载失败后确认按钮保持禁用，成功重读才恢复。关闭弹窗会取消未完成的加载。

## 页面及独立凭证

- 中文 1440px 在真实页面上传图片，按 F2 改名，核对原文件编号、下一版本、原路径、内容哈希和刷新后的名称。Chrome 解码到图片的固有宽度，接口返回的字节与独立读取一致。移除对象后出现日常提示，恢复对象后在原弹窗重试成功。
- 英文 390px 执行同样的上传、改名和重试，Chrome 原生 PDF 查看器显示合成文档正文。浏览器内的读取和独立请求均核对 MIME、内联方式、预览安全策略与实际字节。
- 已授权的业务员可看到同一批发客户的合成文件。客户角色无法通过资料库地址或内容接口访问该文件。两种岗位都使用真实本地登录。
- ZIP 用例注入清单读取拒绝，确认按钮保持禁用。重新加载清单后继续验证真实下载。批量移动、复制及删除的既有中断测试继续使用独立批次及 Storage 凭证。
