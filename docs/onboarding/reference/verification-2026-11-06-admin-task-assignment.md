# 管理员任务改派验证

本批按关键写入验证。过去改派函数调用后只查任务主表，无法确定目标角色。改派现在按任务编号比较写入前后的完整角色集合。已有相同角色时跳过写入，写后集合不符时提示刷新核对。管理员与执行看板共用角色读取。新建和编辑复用类型默认金额和角色选择逻辑，保留手填金额。

## 复现与终态

- 去掉写后集合核对后，合同注入数据库无错误但角色未变，成功断言被检测为错误。恢复核对后 4 项定向合同通过，覆盖相同集合不写入、顺序变化、空集、同数量错角色、错任务、数据库拒绝与类型默认值。
- 无网络、无端口的隔离数据库通过原有授权执行 `set_task_target_roles`。按任务 `b5900000-0000-4000-8000-000000000002` 独立查得 2 行，角色为 `operator` 和 `salesman`。已有领取后再次改派被拒绝，两行保持一致。最初夹具缺角色目录而回滚，补齐三条专属角色后重跑通过。回滚后账号计数为零，容器和临时结构已清理。
- 共享本地项目保持旅游停用。正常登录角色仍无改派函数执行权限，启用计划任务与外部请求队列均为零。隔离 SQL、日志和失败夹具记录在后端仓库 `output/task-assignment-20261106/`。
