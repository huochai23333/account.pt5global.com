# 资料库下载与 ZIP 交付验证

2026-11-05。本地验收复用现有 Web、Auth、Postgres 与 Storage，测试只写入专属合成档案。

在资料库勾选两份文件，打开下载弹窗。故障注入以 HTTP 200 和 `application/zip` 返回非 ZIP 正文。旧页面保存了下载文件并关闭弹窗，错误反馈断言失败。原始日志 `2026-11-05T14-49-51-755Z-0a2261d0-e4ae-4197-bbc6-af850f89e960`。

浏览器读取响应类型、首个文件头及中央目录结尾，匹配本项目生成的单卷无注释 ZIP。只读取固定长度的首尾字节。浏览器格式检查与服务器对象校验分开。服务器在交付前逐项核对 Storage 实际字节、长度和 SHA-256，并复查当前授权清单指纹。单文件下载与打包共用文件内容检查。[ZIP 格式规范](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT)

## 页面与独立凭证

- 中文 1440px 测试替换一份 Storage 对象为等长的错误字节。英文 390px 测试移除其中一份对象。两种情形都保留原文件登记，真实下载接口拒绝交付整包。错误正文也保持弹窗打开，未触发下载事件。
- 恢复对象后，从页面连续点击确认，只产生一次真实下载请求。浏览器保存 `PT5-documents.zip`，解开后两份文件各出现一次。实际字节和哈希均与独立下载的原对象一致。
- 刷新后文件编号、状态、版本和对象路径相同。双击下载的单文件与原内容逐字节相同。未登录使用同一内容地址返回 403。
- 同一轮还复验了批量复制、删除响应丢失后的原批次核对。

共 4 个浏览器用例通过。两种宽度均检查错误弹窗和横向溢出。证据包括 ZIP 中各文件的 SHA-256、页面截图及独立清理回执，位于 `output/learning-document-archive-verified`。浏览器日志 `2026-11-05T14-55-33-295Z-4e8f3c10-210e-493b-9b01-5d855319f2ba`。
