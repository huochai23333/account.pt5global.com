## 复现的断言错误与修复

旧订单版本测试先把上海日期解析成 Date，再使用宿主时区的 setMonth。在洛杉矶时区，以 2026-02-28T16:30:00Z 为当前时间，上海已是三月一日，预期下月月初为 2026-04-01T00:00，旧函数返回 2026-03-01T00:00。

新工具直接在上海年月上计算下月，明确使用 00 至 23 的小时格式。三个宿主时区的子进程分别核对普通月界、跨年、闰日和次日。子进程只加载纯日历模块，不加载认证或管理员辅助文件。原文副本、旧结果和测试标题对照位于 output/learning-parameter-expense-source-review-20261106/。

参数恢复现在核对定义表确实更新一行，并在版本表确认只剩基线版本。订单清理后核对零行。浏览器上下文从准备阶段起进入 finally，即使第二个上下文或页面创建失败、数据清理失败，已创建的上下文仍会关闭。这些原 E2E 收尾断言的运行验证仍未执行。
