# 公告维护与阅读回执验证

2026-11-05。复用既有本地 Web、Auth 和数据库。验收范围包括管理员公告维护、工作台已读批次和内部公告的公开读取边界。

## 缺陷复现与修复

旧弹窗接到单条已读空回执时立即关闭，失败提示随弹窗消失。故障测试从真实工作台发起两条已读，一条返回 HTTP 200 和空正文。修复前断言失败，日志 `2026-11-05T14-30-15-775Z-18067fbe-aec3-482d-ae90-a737c6db2f98`。

页面逐项核对公告编号、当前阅读账号和时间。响应丢失时按原编号查询本人已读记录。只有部分落库时，批次状态为 `partial_failed`，弹窗显示失败项并允许重试。同步锁挡住同一事件中的重复确认。管理页也拆出了行操作和数据库写入服务，受众筛选的「全部对象」与公告受众的「所有角色」使用独立值。

## 页面与数据库凭证

- 管理页从表单创建草稿，按全体受众筛选会排除内部公告。注入发布空回执后原状态和版本保持。实际发布、编辑、下线均由页面发起，同一主键的状态、发布时间和行版本由独立 SQL 读回。删除后该行在数据库和刷新后的列表均消失。两次快速创建只产生一个请求。发布时连续点击也只产生一次实际写入。
- 已读弹窗每种宽度均注入一条空回执。桌面场景同时让另一条真实写入后丢失响应，页面通过读回确定其已完成。重试只提交失败项，之前已读的行版本和阅读时间保持原值。重新加载后无自动弹窗，打开铃铛可看到公告正文。
- 已发布内部公告经过匿名数据库函数读回，匹配行数为零。该检查覆盖匿名函数的当前输出。客户页面的受众矩阵和公开缓存跨周期刷新尚未完成浏览器验收。
