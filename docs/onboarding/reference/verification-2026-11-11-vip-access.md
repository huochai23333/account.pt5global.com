# 批发VIP的岗位、页面和收费凭证

本批对应原计划剩余的批发模块岗位验收。采用`web-change-quality-gate`的关键写入方法，真实Chrome、Next.js、Auth、Data API及数据库函数实际运行，复用唯一3000端口Web。没有外部收款或付款调用。

## 固定范围与当前规则

八个真实登录岗位，各覆盖中文／英文及1440px／390px，共32种页面组合。管理员、财务、业务员从页面分别开通和续期，另外五岗位验证无VIP页面入口及接口拒绝。数据库目录读取范围独立使用页面登录得到的实际令牌验证，凭证只在内存，不写入日志或附件。

| 岗位 | 已启用批发后的数据库读取 | VIP页面及开通续期 |
| --- | --- | --- |
| 管理员、财务、业务员 | 两个本批客户均可读 | 可进入并操作 |
| 经理、操作员、招聘员 | 两个本批客户均可读 | 页面受限、接口拒绝 |
| 客户 | 仅本人关联客户 | 页面受限、接口拒绝 |
| 推广 | 固定业务规则未启用批发，无结果 | 业务暂停页、接口拒绝 |

此表根据当前数据库函数及工作台配置验证，没有修改岗位、业务启用范围或收费权限。可配置岗位只为本次合成账号开通批发；推广不强行开通。数据库读取规则和页面栏目是不同边界，不能以侧栏推断底层权限。详细调用链见[VIP数据流](../explanation/business-vip-flow.md#页面入口读取和操作权限)。

## 真实写入应有什么凭证

每个可操作岗位使用自己的随机客户，从页面同一帧双击确认，开通和续期各只提交一次。独立查询核对收费编号和行版本、200 USD、处理人、前后期限、会员编号及状态；续期保留原会员编号和开始时间，从旧到期时间追加一个日历年。不得产生VIP佣金或额外调整记录。刷新后重新打开历史，记录仍一致。

第二个本批客户作为未操作的对照；两个客户整行及xmin均须不变。收尾先锁住准确客户和记录，再比较完整行／版本，随后只回收本批数据。客户账号自动生成的本人档案保留到账号夹具清理，不误作新建测试客户删除。

额外的缺失目标探针从真实页面发起，传输边界把目标改为独立确认不存在的UUID，仍执行真实路由和数据库。它检查等待中的按钮互斥、明确失败提示、零会员／零收费及刷新后的未开通状态。原有空确认和响应中断回归保持自己的历史记录，本批不重复累计。
