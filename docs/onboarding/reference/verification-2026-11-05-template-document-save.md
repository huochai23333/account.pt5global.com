2026-11-05。复用现有本地 Web、Auth 和 Postgres。用例创建专属模板、目录和账号。草稿创建、自动保存、转正、正式保存与另存为均从实际页面发起。

## 复现与处理

- 转正请求被中止且数据库仍只有原草稿。故障注入的读取结果只给出另一文档编号。旧弹窗关闭并导航，错误提示断言失败。红测日志 `2026-11-05T15-24-17-847Z-628d886c-6dbf-41e6-8c8e-2afb1e3df835`。现仅接受同一草稿编号、固定模板版本、目标目录、名称和填写内容匹配的正式结果。错误结果保留原意图与弹窗。
- 正式保存已落库后丢弃回执。旧编辑器先找回原操作，再做一次强制保存，相同内容的修订号从 2 变成 3。红测日志 `2026-11-05T15-27-12-103Z-27bf047c-56a7-4f1d-8ec5-c8d0cef15ed8`。现有待核对意图时只续办原请求。普通保存取得同步锁后才向 iframe 请求快照，按钮及快捷键共享这一入口。

## 页面与独立凭证

- 中文 1440px 桌面执行全流程。读回另一编号时弹窗保留，数据库没有正式文档。真实转正后再丢回执，关闭弹窗通过只读核对进入同一正式文档。两次转正请求使用同一操作编号，实际转正凭证一份。旧草稿地址显示已转正，并可打开同一正式文档。
- 正式保存丢回执后再次点击重试，数据库记录和修订号保持原值。随后同一事件帧的两个保存点击只产生一个新操作。另存为生成新编号，原文档的修订、名称与内容保持原值。刷新后两个文档的内容均可核对。
- 英文 390px 仅显示既有桌面操作提示，无编辑窗口。使用另一个内部员工登录时，草稿摘要和正式结果均为空，草稿正文返回 404，页面没有编辑窗口。
- 数据库独立计算 JSONB 内容 SHA-256，与原草稿、正式文档和副本的登记值相同。通过真实页面验证收据、终态、刷新和无重复保存。
