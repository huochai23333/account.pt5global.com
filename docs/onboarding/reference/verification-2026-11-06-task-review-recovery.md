# 提审响应中断验证

旅游任务提审属于关键写入。提审从领取记录创建草稿并登记附件，数据库同时更新提交记录和领取状态。原错误路径先清理附件，随后才调用取消。故障注入复现了提交已成功但响应中断时调用附件删除的问题。新的提审流程按同一提交编号、领取编号、操作者、提交状态和时间读回。仅在确认草稿取消后清理文件，无法核对时保留文件并提示用户刷新查看进度。确认草稿已取消但附件未全部清理时报告 `partial_failed`。

## 已验证

- 合同红测重放先删附件的路径，精确断言检测到多余的删除。还原实现后，5 项定向合同通过，覆盖响应丢失、第一次读到草稿而后已审核、取消后清理、错误凭证、删除零影响。Storage 存在性和删除使用网络边界模拟。
- 无端口、无网络的独立 PostgreSQL 容器使用当前结构和真实数据库函数。用事务内的合成账号及两条备注型任务，临时允许提审函数。提交 `63a0f864-1e5e-401a-be9a-05e05b79830f` 为 `pending`，领取 `b5700000-0000-4000-8000-000000000004` 为 `reviewing` 并指向该提交。重复提交和取消已提交记录均被拒绝。另一份草稿取消后查询为零行。事务回滚后专属账号为零，容器已移除。
- 隔离库第一次使用全量种子遇到缺少批发参数版本并回滚，最终用仅涉及提审的专属夹具验证。正式本地数据库查询结果为旅游停用、启用计划任务零、外部请求队列零。
