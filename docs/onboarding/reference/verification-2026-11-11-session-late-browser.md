# 浏览器迟到响应与账号切换

本轮补齐两类边界 × 中英文 × 1440／390px，共8个唯一业务组合，整体仍为 `partial_failed`。修复一处学习登录辅助函数的双语公告处理，未修改生产认证、权限、接口、依赖、迁移或本机连接配置。按 `web-change-quality-gate` 的行为与会话写入范围验收，复用唯一的原 Web。

## 从实际页面到最终凭证

先使用实际登录表单建立本地会话，再进入个人中心。`getCurrentUserBundle` 通过会话读取及数据库岗位组合本人资料。首屏来自服务端，浏览器未必重新请求Auth，因此第一次只打开页面的探针没有捕获目标请求，明确失败。改为在原10秒恢复去抖之后，由Chrome实际离线／在线触发原页面重新同步，再暂存真实响应。[Playwright网络](https://playwright.dev/docs/network) · [Auth事件](https://supabase.com/docs/reference/javascript/auth-onauthstatechange)

所有账号均为随机编号的独占合成账号。浏览器直连本项目48021，不使用替代身份、不改全局角色、不重置数据库。暂存响应先由真实本地Auth或Data API返回，核对当前请求令牌的操作者编号与夹具一致；证据只保留编号，不保存令牌、密码或密钥。

### 退出后的旧Auth响应

捕获原 `/auth/v1/user` 的真实200响应，暂不交付页面。用户从账号菜单点击退出，原生表单进入登录页后，才尝试回送旧响应。四例均观察到原请求 `net::ERR_ABORTED`，浏览器没有收到该请求的成功响应；路由工具接受回送不代表旧页面实际消费了响应。认证Cookie为零，刷新仍显示登录表单，再访问受保护个人中心仍回到登录页。

这是实际退出导航下的取消边界。四类缓存迟到Promise的发布和清理仍由[既有隔离反例](verification-2026-11-06-session-cache-race.md)直接验证，不能把本轮取消请求说成同一页面成功消费了旧Auth结果。SDK记录的 `_getUser` 取消错误与本次同编号的实际中止请求逐一对应；其他错误不被豁免。

### 新账号读取进行中，旧权限响应送达

先从页面把操作员添加为备用账号，再通过原登录表单进入业务员账号。另开同一浏览器上下文的个人中心标签页，恢复同步时暂存业务员的真实数据库权限响应。控制标签页从账号菜单切换回备用操作员，新身份在观察标签页发起实际权限请求之后，再回送旧业务员响应。中文桌面首例还核对新账号资料已显示才回送，后续组合覆盖新请求仍在进行的窗口。

四例旧响应均实际200送达，未被取消；新账号的Auth请求、本人资料查询、操作员工作区和姓名保持一致。独立SQL核对两位专属账号的当前岗位及姓名，刷新后仍为操作员本人。原岗位与权限不变，旧响应没有把新读取替换回旧账号。

SDK的 `getUser()`、`getSession()` 与 `setSession()` 使用令牌锁，不能通过替换SDK来制造任意Auth请求交错。本轮保持真实锁与原8秒读取期限，权限延迟位于实际Data API边界。

## 最终画面门禁与限定重跑

第一轮四个切换组合的账号、响应和数据库断言通过，但人工复核四张截图均仍是加载占位，因此页面门禁失败，没有按正文文字存在就结案。原报告为 `switch-result-before-visual-review.json`，四张原图以 `initial-loading-` 保留，人工失败及图像摘要见 `visual-review.json`。

探针补上资料区实际可见断言，刷新后等待真实网络稳定，再核对姓名、滚动到资料区并确认进入视口后截图。只重跑这四个切换组合，最终四张均显示完整资料；退出四例不重跑，业务场景仍为8个。应用源码未改动，此项是观测等待不足。最终原表摘要和专属账号清理重新核对。

时间字段只用于定位请求，不作业务成功依据。早期探针在清理时再次调用释放，会更新 `releasedAt` 为最后尝试时刻；后续释放改为幂等，另记录真实响应观察时间。旧字段原样保留，不据此宣称精确延迟；真实200送达、当前身份、可见正文及独立SQL才是本轮凭证。

## 修复的测试辅助缺陷

共用 `loginLearningUser` 原先只寻找中文“我知道了”。英文公告仍遮住按钮，导致探针等待30秒，继而产生8秒认证超时和SDK锁警告。该失败保留，未算作业务通过。修正后按实际html语言读取正式公告文案，并等待弹窗关闭；英文桌面及手机退出组合均重跑通过，四个账号切换组合均使用修正后的辅助函数。

改动仅 `scripts/learning/local-fixture-session.mjs`，174→180行，仍负责本地SQL、专属账号生命周期、真实页面登录三项职责。已复核整份文件、调用链与摘要并更新人工审查记录，没有新增待审源码。没有为公告变化修改产品界面或认证算法。

## 证据、清理和剩余范围

证据位于Web `output/learning-session-late-browser-20261111/`。`browser-result.json` 与 `switch-result.json` 分别记录四个组合、响应是否实际到达、请求身份、数据库岗位和刷新结果；`baseline.json` 保存13表摘要与后台任务基线，`console-check.json` 区分预期取消和额外错误，`final-verification.json` 核对全部原始日志字节及SHA-256、应用输入与源文件摘要。

首轮未捕获请求和英文弹窗遮挡两次失败、每轮重跑、修复前源码及人工记录分别保留。已完成的中文退出场景不重复计数。8张截图按唯一组合命名，控制标签与观察标签的异常分别核对。

所有账号、布局、Auth会话和刷新令牌均限定清理并读回为零。公告已读表的实际外键为 `ON DELETE CASCADE`，本次账号删除后另核对其已读标记为零。原Auth用户、岗位、客户、文档、模板及Storage的13表行数、内容及 `xmin` 摘要恢复原样；计划任务暂停、外部请求队列为空。未启动第二个Web，也未创建代理、临时数据库或外部供应商。

最终使用npm11.16.0运行学习检查、doctor，并核对当前应用的1142份构建输入保持原字节，因此不重复执行不相关的生产构建。原受限认证入口及完整套件、完整注册、OTP、改密、真实第三方及其他剩余业务矩阵继续分别验收。本轮本地结果不代表上传、Cloud变更或网站部署。维护入口见[认证读取链路](../explanation/auth-read-paths.md)和[改造报告](../implementation-report.md)。
