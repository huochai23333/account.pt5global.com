## 发现与改动

原用例以 350 或 500 美元取第一行，遇到同金额或中断遗留订单时会选错。原清理用备注前缀取得全部匹配订单，还会删除附件登记。现在由页面发起写入，校对同一 API 的目标参数和成功响应，用新订单 ID、数据库订单号、版本及对应审计记录串联后续步骤。

清理事务在专属实例先锁表，再比对所有纳入范围的行及 `xmin`，逐表按 UUID 和期望行数删除。任何未确认写入、外来版本、附件、未知级联或影响行数不符都会停止清理。清理后用独立连接重读，核对原记录和 Storage 对象目录。生产路由、角色权限、金额算法及迁移未修改。[PostgreSQL 锁](https://www.postgresql.org/docs/16/explicit-locking.html) · [行版本](https://www.postgresql.org/docs/16/ddl-system-columns.html)
