# 项目术语表

| 术语 | 在本项目中的含义 |
| --- | --- |
| 工作台 / workspace | 角色对应的页面空间，例如 admin、salesman；不是另一套数据库 |
| 业务 / business | 批发或旅游；当前启用状态由公司配置和业务清单决定 |
| 栏目 / section | 订单、线索、物流等业务入口 |
| Page / renderer | Page 识别路由和访问前提；renderer 选择业务首屏数据和页面组件 |
| Server Component | 在服务器执行的 React 组件，适合读取首屏与会话 |
| Client Component | 承接浏览器交互的组件，不能导入服务密钥 |
| Hook / view-model | 组织页面交互状态、请求和恢复的函数；通常以 use 开头 |
| query | 读取数据，重点是权限、字段范围、排序、分页与超时 |
| mutation | 修改数据，必须处理输入、权限、并发和最终凭证 |
| RPC / 数据库函数 | Web 调用受控数据库逻辑的接口，复杂规则可能在 SQL 内 |
| RLS | 数据库按当前身份限制可见或可修改的行 |
| Storage | 文件对象存储；数据库登记和文件字节是两份需要核对的事实 |
| migration / 迁移 | 按版本应用的数据库变更；历史文件不等于当前完整定义 |
| Edge Function | Supabase 侧的后台 HTTP 函数，可调度同步、媒体处理等 |
| operation / 运行凭证 | 一次业务操作的持久化编号、尝试与终态 |
| 幂等 | 同一业务意图重试不会重复创建业务效果 |
| revision / version | 防止旧窗口覆盖新数据的版本或修订号 |
| partial_failed | 多项处理部分完成，仍有失败项需要处理 |
| fixture / 夹具 | 为测试独立准备、有归属且可限定清理的数据 |
| E2E | 从真实页面到后台结果的整条测试链路；模拟提供商需单独说明 |
| snapshot / 快照 | 操作时固定下来的规则或记录内容；历史订单不能随新规则随意变化 |

技术词汇用于开发资料。面向用户的网页提示应使用日常语言。
