# 三个小改动：文案、展示字段与筛选

先在本地使用自己的练习分支或工作副本，记录原有差异。练习完成后只撤回自己增加的行，不覆盖他人修改。下面练习不需要修改数据库规则或真实业务数据。

## 准备两条练习线索

运行 `doctor`，复用已有本地 Web 服务。使用本地学习管理员打开 `/admin/wholesale/leads`。在后端仓库按[线索夹具步骤](sales-lead-flow.md#准备独立预期)生成两个 UUID，各创建一条线索。让第一条留在大厅，首次联系为空。用页面认领第二条并记录一次联系，核对数据库凭证。把这两条编号分别记为「空值样本」和「日期样本」。

两条线索的标题包含练习 UUID，可以用来检查手机换行。结束时分别按原编号清理，独立读取两条及其关联计数，刷新页面后确认不再显示。

## 练习一：改一条双语说明

目标是在本地线索页看到一条自己的说明，并理解文案怎样到达页面。

1. 在 `messages/zh.json` 找到 `SalesLeads.header.description`，同时找到英文文件中的相同键。
2. 在两种语言的原说明后增加一句对应的练习提示，保留原业务含义。
3. 打开 `components/dashboard/sales-leads/sales-leads-client.tsx`，找到 `useTranslations("SalesLeads")` 和 `t("header.description")`。
4. 沿批发 renderer 确认页面已下发 `SalesLeads` 命名空间。
5. 执行 `npm run check:i18n`，打开有权限的本地线索页，切换中英文，分别检查 1440px 与 390px，并刷新。

预期：两种语言都显示对应提示，没有丢失消息、横向溢出或错误遮罩。静态检查通过但页面没变化时，先确认打开的服务与仓库，以及 provider 的命名空间。

## 练习二：增加一个只读展示字段

目标是展示已经允许下发的数据，不扩大查询权限。

1. 阅读 `lib/sales-leads-types.ts`，选择已存在、允许为空的 `first_contact_at` 字段。它已在详情中展示，本练习把它增加到列表跟进区。
2. 找到 `SalesLeads.fields.firstContact` 的中英文标题，复用已有键，避免为同一含义增加重复文案。
3. 在 `sales-lead-list-row.tsx` 的 `list.followUp` 区块增加日期。标签用 `t("fields.firstContact")`，值用 `formatLeadDate(lead.first_contact_at, locale)`。桌面和手机共用这行组件。
4. 在 `sales-lead-cards.tsx` 的 `MetaGrid` 用 `MetaItem` 展示相同标签和值。两种布局复用同一个格式工具。
5. 执行 lint、typecheck、i18n 和结构检查。大厅空值样本显示 `—`。打开「我的线索」，按日期样本编号搜索，核对实际联系时间在列表和卡片里一致。中英文、1440px 和 390px 都检查一次。刷新后重新选择「我的线索」和同一编号。

预期：显示值来自该线索原有数据；切换视图与刷新后相同。若字段没有出现在实际响应，先查查询合同，不用类型断言伪造数据，也不直接扩大到 `select("*")`。

## 练习三：为已有搜索条件增加快捷入口

1. 使用线索教程的专属夹具准备一条 `country=CN` 的大厅线索，记下唯一编号；不恢复共享账号或改现有线索。
2. 阅读 `use-sales-leads-list.ts` 中 search、refreshTimer 和 requestVersion 的关系，以及 `lib/sales-leads.ts` 如何传递 `p_search`。
3. 给两种语言新增 `SalesLeads.filters.practiceSearch`，标题分别为“搜索 CN”和“Search CN”。在 `sales-leads-toolbar.tsx` 的搜索框旁增加调用 `onSearch("CN")` 的按钮，并用中文注释说明复用现有服务端查询。
4. 页面点击快捷按钮，确认输入框变为 `CN`，能找到仍在大厅的空值样本。手动搜索 `US`，核对自己的样本消失。再输入独有且不存在的词，确认空结果文案出现。最后再次点击快捷按钮恢复。搜索匹配多个字段，按钮使用「搜索 CN」。
5. 中英文及 1440/390px 都检查一次，确认字段、按钮和列表无全局横向溢出。刷新会恢复页面原有搜索初态，不应声称新增了筛选持久化。
6. 清理专属夹具，只撤回本次文案、字段与按钮改动，保留练习前已存在的工作。

预期：快捷入口改变实际查询条件，分页及授权仍由既有服务端合同处理。进一步练习可在慢速网络中快速切换关键词，核对旧请求不会覆盖新条件；这项需要单独记录，不由按钮可点击推断通过。

完成后能够指出：文案在哪、字段来自哪、状态由谁管理、为什么旧请求不能覆盖新请求，以及本次验证尚未覆盖什么。

[前端练习复走记录](../reference/verification-2026-11-11-front-tutorials.md)保存了页面矩阵、筛选结果、真实日期和恢复凭证。
