# 排查顺序

先运行 `npm run doctor`，再按下表定位。诊断只读，不自动改环境、启动服务或重置数据。

| 现象 | 先核对 | 下一步 |
| --- | --- | --- |
| Docker 无法连接 | Docker Desktop 引擎是否就绪 | `docker version`，不把客户端进程存在当成引擎健康 |
| Auth 容器启动时重启 | 数据库、Auth 健康与启动时序 | 等待健康检查；持续重启再看脱敏日志 |
| Vector 重启 | 日志源连接的 Docker 接口 | 见后端环境说明；不要为排查开启无保护的远程 Docker 端口 |
| 登录失败但刷新恢复 | 密码请求、已有会话、后续权限读取分别观察 | 看恢复入口和脱敏阶段日志，不反复自动提交密码 |
| 账号页错误 | 本地服务端管理配置、真实角色与正文 | 配置存在不等于页面通过，首次打开和刷新都需检查 |
| 列表为空 | 当前角色、筛选日期、数据归属和权限 | 不立即把空列表解释为数据库无记录 |
| 双语消息缺失 | 两种消息键与 provider 命名空间 | 运行 i18n 检查并打开实际页面 |
| 后台调用未完成 | 函数服务、操作编号、终态与独立凭证 | 不能只看请求 2xx 或任务已创建 |
| E2E 审计失败 | 历史集合、当前清单与映射 | 先核对具体新增/删除/改名，不直接改总数 |
| 构建无法创建 worker | 构建进程和项目现有 CPU 限制 | 按现有 Next 配置验证完整构建，避免同时运行两个 dev server |

遇到新问题，先查官方资料并核对本项目版本，再修改。报告保留最小可复现步骤、实际错误分类和结果，勿输出完整环境、Cookie、令牌或请求正文。
