# 公司模板线上故障修复验证

## 线上已确认的原因

2026-10-08，在已登录的线上管理员页面复现并读取同一文档正文：

- 形式发票当前 v4，版本 `33c01bb7-af55-4fbf-a2aa-321010561cf2`，HTML 中没有 `PT5Template`。事务入口拒绝新建个人文档，显示“这份模板暂时无法保存”。
- 报价单当前 v5，具备保存接口。正文实际返回 200 并渲染，但桥接配置的 `parentOrigin` 是 `https://0.0.0.0:3000`，浏览器父页面为 `https://account.pt5global.com`，就绪通知与初始化消息不能完成。
- 当时云端有 5 份报价单个人文档，均 revision 1、空状态 `{}`。本次线上检查只读，没有更改这些记录。

## 修复范围

正文路由复用既有公开地址策略；生产环境使用配置的站点公开域名，不采用内部请求 URL 或任意转发头。保留窗口来源、沙箱来源、随机标识、权限与哈希校验。编辑页加载失败后明确显示失败和重试，不继续显示“正在打开文档”。

形式发票新增独立保存接口源模块与迁移 `20261008133725_invoice_personal_document_protocol.sql`。迁移锁定已核对的 v4，发布下一个不可变版本，原 HTML、指南和已有文档绑定不变；当前源版本若变化则停止。保存填写字段、动态明细、付款卡片、图片、自定义比例与币种、手动编号、打印设置，以及本人文档内的公司与付款信息库。

## 质量门路线与业务凭证

使用 `web-change-quality-gate` 的 Critical write 路线：管理员从真实页面上传版本 → 页面新建与填写 → 独立本地 Supabase 查询确认 ID、绑定版本、修订号、哈希与填写数据 → 刷新恢复相同内容。

使用的唯一开发服务为 `http://localhost:3100`；启动前确认该项目没有其他运行中的服务。3000 端口属于另一个项目，未修改。
