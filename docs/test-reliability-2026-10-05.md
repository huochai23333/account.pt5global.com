## 实际整改

1. 分页独立预期原先使用 `Date.parse`，相差一微秒的记录被截成相同毫秒。新增手写顺序用例在旧实现下实际失败；现在独立解析明确时区的时间，使用 BigInt 保留六位微秒，同一时刻才按 UUID 降序。拒绝无时区、非法日期/时钟/偏移和超过六位小数的夹具时间。该解析器只服务合成测试清单。
2. 重复 ID、重复包裹、缺少记录与非合成清单分别注入，每项核对对应失败原因。页面负例同样核对业务控件、标题、错误正文或遮罩的具体断言，防止任意异常造成假通过。
3. 页面检查增加隐藏标题/控件、正文外控件、重复 main 和框架遮罩；1440/390px 的独立 HTML 文档重新加载后仍须满足约定。HTTP 夹具明确声明 UTF-8。这些只是受控文档检查，不是产品响应式验收。
4. 运行记录新增 stdout/stderr 原始字节数、SHA-256、证据版本；独立 CLI 拒绝日志缺失、摘要不一致、缺摘要记录及中断却宣称成功的记录，保留原测试失败退出码。核验不会重新执行原命令，也不能恢复已覆盖的历史日志；摘要不是签名，不能检出日志和记录一起被改写。
5. 相邻 Supabase 仓库仅增加 Storage 回调单元测试：逐个对象核对、第二个对象失败时停止、身份/权限/限流/服务错误、错误类型不符、数据与错误矛盾、读取直接抛错。预期不由被测函数生成，错误用对象身份或具体原因核对。
